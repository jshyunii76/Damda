# 1바퀴 기획 — 팀원끼리 같은 방을 진짜로 함께 쓰기

> 작성: 2026-11-24 · 대상 코드: `pikachu515/Damda` (원본 `jshyunii76/Damda` 커밋 a8a5e7c 기준)
> 표기: 📁 코드 확인 / [판단] 미확인 추정

## 1. 한 문장 목표
**팀장이 만든 방 코드를 팀원이 자기 폰에서 입력하면, 같은 메모·사진·할 일을 함께 보고 쓰고, 방 안에 "누가 들어와 있는지" 이름으로 보인다.**

## 2. 왜 이것부터 하나
- 비튼 BMC의 킥은 "팀플방에서 떠들면 자료·결정·할 일·기여가 자동으로 남는다"이다. **여러 사람이 같은 방을 실제로 쓰지 못하면 기여 기록(2바퀴)도, 정리 리포트(3바퀴)도 성립하지 않는다.**
- 교수님 질문 "왜 나와의 채팅에서 넘어오나"에 대한 답이 "팀이 함께 넘어온다"인데, 지금은 그 '함께'가 동작하지 않는다.

## 3. 지금 상태 (코드 근거)
| 항목 | 현재 | 근거 |
|---|---|---|

| 공유방 저장 위치 | `s:room:코드` 키로 **각자 자기 계정의 kv 줄**에 저장 | 📁 `index.html` 2104~2108, 1496~ |

## 4. 사용 장면
1. **팀장 상현**: 담다에 카카오로 로그인 → "경영학 5팀" 방 생성 → 공유 → 코드 `K7Q2MX`를 단톡에 붙여 넣음.
2. **팀원 우진**: 담다 설치·로그인 → 방 참여 → 코드 입력 → 방 목록에 "경영학 5팀 · 공유 중 · 5명".
3. 우진이 발표 자료 사진을 올리면 **상현 폰에도** 몇 초 안에 뜸. 상현이 마감 "11/30 PPT 초안"을 걸면 모두의 일정에 뜸.
4. 방 정보에서 **참여자 이름 목록**(상현·우진·승호·관우·정윤)이 보임.
5. 관우가 방을 나가면 목록에서 빠지고, 방과 기록은 남은 사람에게 그대로 남음.

## 5. 범위
**넣는 것 (1바퀴)**
- R1. 서버에 '방'과 '방 멤버'를 따로 둔다. 방 데이터는 **멤버 누구나** 읽고(권한에 따라) 쓸 수 있다.
- R2. 코드로 참여하면 멤버로 등록된다. 공유하려면 로그인이 필요하다(로그인 안 하면 "공유하려면 로그인하세요" 안내).
- R3. 참여할 때 **방에서 쓸 이름**(기본값: 카카오/구글 이름)을 정한다. 방 정보에 멤버 이름 목록을 보여 준다.
- R4. 다른 멤버가 쓴 메모·사진·마감이 내 폰에 반영된다(새로고침 또는 자동).
- R5. "보기만" 권한을 **서버에서도** 막는다.
- R6. 사진·파일도 멤버끼리 볼 수 있다.
- R7. 이미 만들어 둔 공유방(내 kv에 있는 `s:room:`)을 새 구조로 옮긴다.

**빼는 것 (다음 바퀴 이후)**
- 메모별 작성자 표시, 할 일 담당자 → 2바퀴
- 팀플 정리 리포트 → 3바퀴
- 푸시 알림, 읽음 표시, 강퇴·방장 위임

## 6. 완료 기준 (피드백 단계에서 이대로 시험)
| # | 시험 | 통과 조건 |
|---|---|---|
| T1 | 폰 A(계정1)가 방 공유 → 폰 B(계정2)가 코드 입력 | B 방 목록에 방이 생기고 A의 기존 메모가 보임 |
| T2 | B가 메모·사진 작성 | 10초 안에(또는 새로고침 후) A에서 보임 |
| T3 | 방 정보 열기 | 두 사람 이름이 모두 보임 |
| T4 | 권한 '보기만'으로 바꾼 뒤 B가 쓰기 시도 | 화면에서 막히고, **서버에 직접 요청해도 거절** |
| T5 | 방 멤버가 아닌 계정3이 코드 없이 방 데이터 요청 | 거절 |
| T6 | A와 B가 오프라인에서 각각 메모 작성 후 재접속 | 두 메모 모두 남음(하나가 덮어쓰지 않음) |
| T7 | B가 나가기 | A의 멤버 목록에서 빠지고 방 기록은 유지 |
| T8 | 1바퀴 전 공유방이 있던 계정으로 접속 | 기존 공유방 메모가 사라지지 않음 |

## 8. 정해야 할 것 / 위험
- **서버 변경은 상현 님 Supabase에서 실행**해야 한다. 우리는 SQL 파일과 앱 코드까지 만들고, 적용은 부탁한다. (원본 저장소는 CODEOWNERS로 상현 님 승인 필요 📁 커밋 c12a406)
- **코드 추측 공격**: 6자리 × 32글자 ≈ 10억 가지. 많지는 않으므로 참여 시도 횟수 제한을 설계에서 검토. [판단]
- **동시 수정 충돌**: 지금은 방 전체를 한 덩어리로 저장하고 기기 쪽에서 합친다(📁 `merge3`). 여러 명이 동시에 쓰면 덮어쓰기 위험이 커진다 → 설계에서 '메모 1개 = 서버 1줄' 구조로 바꿀지 결정.
- **무료 요금제 한도**(저장 용량·동시 접속): 설계 단계에서 Supabase 요금 페이지 원문 확인.
- **개인정보**: 방 멤버에게 내 이름이 보인다 → 참여 화면에 고지, `privacy.html` 문구 보완 필요.
