## 무엇이 바뀌나
지금 공유방은 각자 폰에 방 전체를 통째로 저장하고 서로 합치는 방식이라, 여러 명이 쓰면 덮어쓰기·권한 우회가 생길 수 있었어요. 이걸 Supabase 표 3개로 옮겼어요.

- `rooms` (방) · `room_members` (멤버, 이름 포함) · `room_msgs` (메모 1개 = 1줄)
- **코드로 참여**할 때 방에서 쓸 이름을 입력하고, 공유 시트에 "함께 쓰는 사람 N명 · 이름(방장), …"이 보여요
- **'보기만'을 서버(RLS)에서 막아요** (지금은 화면에서만 막음). 방장이 권한을 바꾸면 열려 있는 화면에도 바로 반영돼요
- 작성자(`author`)·마지막 수정자(`edited_by`)를 **서버가 자동 기록** — 다음 단계(작성자 표시·기여 기록)의 바탕
- 사진은 `files/r/방ID/파일ID`에 저장돼 방 멤버 모두 볼 수 있어요
- 실시간 반영, 인터넷이 끊긴 채로 쓴 글은 연결되면 올라감
- **기존 공유방은 로그인하면 자동으로 새 구조로 옮겨져요** (방장 방은 같은 코드로, 참여했던 방은 자동 재참여)
- 개인 메모(`kv`) 동기화는 그대로예요

## 합친 뒤 해야 할 일 (상현)
1. Supabase 대시보드 → **SQL Editor**에 `supabase/rooms.sql` 전체를 붙여 넣고 **Run** (여러 번 실행해도 안전)
2. "Potential issues detected" 창이 뜨면 내용 확인 후 실행 (`drop policy if exists` 때문에 '파괴적 작업' 경고가 뜰 수 있어요)
3. SQL을 실행하기 **전에** 새 앱이 배포되면 공유·참여가 실패해요 → **SQL 먼저, 그다음 합치기** 순서를 추천해요

## 시험한 것
- **SQL 권한 시험 50개** (PGlite로 Supabase 흉내: 멤버 아님·보기만·작성자 위조·코드 맞히기 제한·나가기 등) — `cd tests && npm install && npm test`
