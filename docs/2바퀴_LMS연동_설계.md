### 1-1. 한양대 HY-ON(LearningX) 실제 피드에서 확인한 형식 ✅ (2026-11-25, 승호 님 계정, 형식만 기록 — 과목·과제명·주소는 기록 안 함)
| 항목 | 실제 모양 | 설계 반영 |
|---|---|---|
| 주소 | `https://learning.hanyang.ac.kr/feeds/calendars/user_<토큰>.ics` | 경로 검사 `/feeds/calendars/user_*.ics` 확정 |
| 응답 | `text/calendar`, 약 49KB, 일정 24개, `PRODID:icalendar-ruby`, **VTIMEZONE 없음** | |
| CORS | 같은 사이트에서 받아도 `Access-Control-Allow-Origin` 헤더 **없음** | 서버 대리 받기 필요 확정 |
| UID | 24개 모두 `event-assignment-<숫자>` | 고유번호로 그대로 사용, 종류=과제 |
| 제목 | `과제 제목 [<학기·과목코드>_<과목명(…)>]` — **끝 대괄호 = 과목** (과목당 대괄호 값 1개로 일정함). 제목 **앞에도** `[…]`가 붙는 경우 있음 | **마지막** 대괄호만 과목으로. `_` 뒤를 과목 이름으로 표시 |
| URL | `/calendar?include_contexts=course_<숫자>&month=…&year=…#assignment_<숫자>` | `course_<숫자>`로 과목 묶기 (5과목 확인) |
| 마감 시각 | ① `DTSTART:20261117T135900Z`(UTC) ② `DTSTART;VALUE=DATE:20261106T000000` — **날짜형인데 시간이 붙은 비표준 모양** | ①은 서울 시간으로 변환(13:59Z → 22:59), ②는 날짜만(시간 없는 마감). 시작=끝 |
| 설명 | DESCRIPTION 최대 약 3.5KB, `X-ALT-DESC`(HTML) 따로 있음 | 메모엔 안 넣고 Canvas 링크만 |
| 퀴즈·시험·팀 단어 | 현재 24개 중 0개 | 규칙은 가짜 샘플로 시험 |

**결정 변경:** ②처럼 표준과 다른 날짜 모양이 있어 **ical.js 대신 30줄짜리 자체 해석기**를 쓴다 (줄 이어붙이기·`\,` `\;` `\n` 풀기·위 두 날짜 모양만 처리). 외부 라이브러리를 안 불러도 돼서 더 가볍다. A8 항목 삭제.

## 2. 전체 구조
```
[담다 앱]  --(로그인 토큰 + 피드 주소)-->  [Edge Function canvas-feed]  --GET-->  [학교 Canvas /feeds/calendars/…ics]
    ^                                              |
    └────────────── .ics 텍스트 ───────────────────┘
  ical.js로 해석 → 과목방(개인방) + 마감 할 일 메모 → 팀 과제면 '팀플방 만들기' 제안
```
- 서버에 **새 표 없음**. 피드 주소는 기존 개인 동기화(`kv`, 본인 줄만 RLS)에 `p:lms` 키로 저장 → 다른 기기에서도 연결 유지 📁 `setup.sql`
- 받은 일정은 **개인방 메모**로 들어감 (공유방 아님) → 1바퀴 동기화 그대로 사용

## 3. 서버: Edge Function `canvas-feed`
| 항목 | 결정 | 이유 |
|---|---|---|
| 호출 | `POST {url}` · Supabase 로그인 토큰 필수(기본 JWT 검사) | 로그인한 사람만 |
| 주소 검사 | `https:`만 · 경로가 `/feeds/calendars/` 로 시작하고 `.ics`로 끝남 · 호스트가 IP·`localhost`·내부 주소면 거절 | **아무 주소나 대신 받아 주는 '열린 프록시'/내부망 접근(SSRF) 막기** |
| 받기 | 10초 제한 · 응답 2MB 넘으면 중단 · 리다이렉트 따라가지 않음 | 느린/큰 응답으로 함수 묶이지 않게 |
| 돌려주기 | `text/calendar` 본문 그대로 · CORS는 담다 주소(GitHub Pages·localhost)만 | |
| 기록 | **피드 주소를 로그에 남기지 않음** (호스트만) | 주소 = 열쇠 |
| 실패 | Canvas가 404/401 → `{error:'feed'}` (주소가 바뀌었거나 만료) / 그 외 → `{error:'net'}` | 앱이 안내 문구를 고름 |

시험용 프로젝트(DAMDA-TEST)에는 대시보드의 Edge Function 편집기로 배포. 상현 님 운영 서버엔 3바퀴 PR 때.

## 5. 규칙
### 5-1. 일정 종류(kind)
- 제목·UID에 `quiz|퀴즈|쪽지` → **퀴즈** / `exam|시험|중간|기말|midterm|final` → **시험** / UID에 `assignment` 있음 🔎 → **과제** / 나머지 → **일정**
- 메모 글 앞에 `[과제]` `[퀴즈]` `[시험]` 표시 (담다의 기존 `[회의]` 분류와 같은 모양 📁 PR #1·#2의 회의 분류)

### 5-2. 과목 이름 (🔎 샘플로 확정 — 그 전엔 아래 순서로 시도)
1. 제목 끝 `[과목]` 대괄호
2. 일정 링크(URL)의 `/courses/숫자` → 같은 숫자끼리 한 과목으로 묶고, 이름은 1번에서 얻은 것 사용
3. 둘 다 없으면 `Canvas` 방

### 5-3. 메모 모양 · 중복 방지 · 고침 반영
```js
{ id:'c'+짧은해시(uid), ts:받은시각, text:'[과제] 3장 보고서',
  due:'2026-12-03', dueTime:'23:59',            // 서울 시간으로 변환
  lms:{ src:'canvas', uid, url, course, kind, sum:지문 } }
```
- **같은 uid 메모가 이미 있으면 새로 안 만듦** (방 전체에서 `lms.uid`로 찾음 → 사용자가 다른 방으로 옮겨도 중복 안 생김)
- Canvas에서 제목·마감이 바뀌면(`sum` 지문 다름) → 메모의 `text·due·dueTime`만 고침. **완료 표시·메모(note)·고정 등 사용자가 한 것은 그대로**
- 사용자가 글을 직접 고친 메모는 글을 덮어쓰지 않고 마감만 고침

### 5-4. 피드에서 사라진 일정
- 마감이 **오늘 이후인데** 피드에서 사라지면 → 지우지 않고 글 끝에 `(Canvas에서 사라짐)` 표시
- 지난 일정은 피드가 오래된 것을 빼고 줄 수 있으므로 **아무것도 안 함** (1장, 🔎 샘플로 확인)

### 5-5. 팀 과제 감지
- 제목에 `팀|조별|그룹|프로젝트|team|group|project` → 제안 버튼 (A6). **자동으로 방을 만들지 않음** [판단: 피클의 '확인 없이 실행' 논란 회피 — 기획 3장]

1. **샘플 .ics 확보** (승호 님 → `Damda/` 폴더, 커밋 안 함 — `.gitignore`에 `*.ics` 추가) → 5-2 규칙 확정, 가짜 데이터로 시험용 `tests/fixtures/sample.ics` 만들기(실제 과목·주소 없이)
